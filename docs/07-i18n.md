# 07. 이중 언어(한국어·영어) 아키텍처

AI/Data North Pole은 UI·데이터·문서를 한국어/영어 두 언어로 제공한다.
원문은 어느 언어로 작성해도 되고, 반대 언어 번역은 `/translate` 클로드 스킬이 채운다.
원문 언어는 텍스트의 한글 포함 여부로 자동 판별한다 (한글 있음 → 한국어 원문).

## 구성 요소

| 영역 | 원문 | 번역 저장 위치 | 표시 방식 |
|---|---|---|---|
| UI 문자열 (버튼·라벨·안내문) | 코드 안의 한국어 | `public/assets/i18n-dict.js` (exact + patterns) | `i18n.js`가 영어 모드에서 텍스트 노드·속성을 표시 시점에 치환 |
| 사용자 작성 데이터 (Goal, 프로젝트명, 태스크, 요청 등) | `data/db.json`의 필드 원문 | 같은 레코드의 `i18n.{ko,en}` 사이드카 | 서버가 `/api/state?lang=`에 맞춰 필드를 치환해 응답 |
| 문서 (README, docs/*.md) | 한국어 .md | `README.en.md`, `docs/en/*.md` | 정적 파일 |

## 동작 규칙

- **언어 전환**: 상단바의 언어 버튼(English/한국어). 선택은 `localStorage("northpole-lang")`에
  저장되고 새로고침으로 화면·데이터가 함께 전환된다.
- **UI 번역**: `i18n.js`가 MutationObserver로 동적 렌더링까지 감시하며
  사전(`i18n-dict.js`)의 exact/pattern으로 치환한다. alert/confirm/prompt 메시지와
  서버 오류 메시지도 같은 사전으로 번역된다. 사전에 없는 문자열은 한국어로 남는다
  (누락 후보 확인: `node scripts/i18n-scan.js --ui`).
- **데이터 번역**: 레코드에 `i18n: { en: { <field>: <번역>, _src: { <field>: <번역 시점 원문> } } }`
  형태로 저장한다. `_src`가 현재 원문과 다르면 "낡은 번역"으로 재번역 대상이 된다.
  번역 대상 필드 목록은 `server.js`의 `TR_FIELDS`(스캐너와 동일 기준)에 정의:
  조인 키(product.name, project.dept)와 상태·단계 토큰은 번역하지 않는다 —
  이들의 표시 번역은 UI 사전이 담당한다.
- **편집 무결성**: 영어 모드에서 폼을 저장할 때 값이 기존 번역본과 동일하면 원문을
  건드리지 않는다(무변경). 값이 실제로 바뀌면 그 값이 새 원문이 되고 해당 필드의
  기존 번역은 폐기된다 — 다음 `/translate` 실행 때 재번역된다. (`server.js`의 `updTr`)
- **필터·저장 값 안전성**: 상태·채널 등 로직에 쓰이는 `<option>`은 전부 `value` 속성에
  한국어 토큰을 고정해 두었다. 화면 표기만 번역되고 저장·비교 값은 변하지 않는다.
  새 select를 추가할 때도 반드시 `value`를 명시할 것.

## 번역 워크플로 (/translate 스킬)

```bash
node scripts/i18n-scan.js --list          # db.json 미번역·낡은 번역 목록
node scripts/i18n-scan.js --apply f.json  # 번역 결과 병합 (적용 후 서버 재시작 필요)
node scripts/i18n-scan.js --ui            # UI 사전 누락 후보
node scripts/i18n-scan.js --docs          # 영어본 없는/오래된 문서
```

스킬 정의: `.claude/skills/translate/SKILL.md`. Claude Code에서 `/translate`로 실행하면
위 스캐너로 미번역분을 찾아 번역·적용까지 수행한다.

주의: `--apply`는 `data/db.json`을 직접 수정한다. 서버는 db를 메모리에 캐시하므로
적용 후 **서버를 재시작**해야 반영된다 (서버가 켜진 채 적용하면 이후 서버 저장 시
덮어써질 수 있음 — 가급적 서버를 멈추고 적용).
