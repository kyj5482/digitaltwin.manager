# 03. 프론트엔드 기능 요구사항

프로토타입 화면(`prototype/*.html`)과 1:1로 대응한다. FR 번호는 구현 티켓의 기준 ID.

## 0. 공통

| ID | 요구사항 |
|---|---|
| FR-000 | 본 모듈은 기존 서비스(Digital Twin Manager)의 **세부 메뉴 그룹 "AI/Data North Pole"** 으로 편입된다. 별도 로그인 없이 기존 세션·권한을 상속한다 |
| FR-001 | 메뉴 구성(순서 고정): 대시보드(North Pole) / KPI 모니터링 / Product & Goal / 프로젝트 / 스프린트 보드 / 요청 Intake — KPI에서 출발해 Goal·프로젝트로 내려가는 흐름. 태스크 상세는 보드·목록에서 진입 |
| FR-002 | 라우팅(제안): `/northpole/dashboard`, `/northpole/products`, `/northpole/projects`, `/northpole/projects/:id/board?sprints=…`(프로젝트 스코프 스프린트 보드), `/northpole/tasks/:id`, `/northpole/requests` |
| FR-003 | 라이트/다크 테마 지원. 기존 서비스에 테마 설정이 있으면 그 값을 따른다 |
| FR-004 | 모든 목록은 검색 + 필터(부문/상태/담당자 등) + 정렬을 지원하고, 필터 상태를 URL 쿼리에 보존한다 |
| FR-004a | **페이지네이션**: 목록이 페이지 크기를 초과하면 페이저(‹ 이전 · 번호 · 다음 ›, 「총 N건 중 a–b 표시」) 표시. 페이지 크기 10/25/50 선택(기본 50). 필터·검색 변경 시 1페이지로 리셋, 페이지 이동 시 스크롤 최상단. 서버 페이지네이션(`?page,size`)과 연동 |
| FR-005 | 사용자 표시는 아바타(이니셜) + 이름. 이름에 툴팁 |
| FR-006 | 상태·우선순위 배지는 **아이콘+텍스트를 항상 동반** (색만으로 의미 전달 금지 — 접근성) |
| FR-007 | 날짜는 `YYYY-MM-DD`, 시간 포함 시 24시간제. 소요시간은 "N일 N시간" 표기 |

## 2. Product & Goal (`products.html`)

| ID | 요구사항 |
|---|---|
| FR-200 | 부문(Product) 카드 그리드. 카드에 Goal 문장, Goal 상태 배지(초안/구체화중/확정), 오너, 마일스톤 목록(기한·진행률 미터), 프로젝트 수 요약 |
| FR-201 | 연도 셀렉터 — 과거 연도 Goal은 읽기 전용으로 열람 |
| FR-210 | Goal 편집 모달: **프로덕트(부문) 셀렉터로 편집 대상 선택** — 카드의 [✎ Goal 편집]에서 열면 해당 부문이 프리셋되고, 셀렉터 변경 시 그 부문의 Goal이 로드된다. 문장(필수), 상태, 오너, KPI(선택 — 미정 허용). 저장 시 변경 이력(goal_history) 자동 기록, 변경 사유 필수 |
| FR-211 | Goal 변경 이력 열람 (누가/언제/무엇을/왜) |
| FR-220 | **마일스톤 추가/수정 모달**(카드별 [+ 마일스톤], 행별 [⋯] → 수정): 코드 자동 채번(Mn — 삭제로 번호가 비어도 최대 번호+1로 중복 방지), 이름(필수), 기한(분기), 보류 상태. 진행률은 소속 프로젝트 진행률 가중 평균(태스크 수 기준)으로 **자동 계산 — 읽기 전용**. 수정 시 변경 사유 입력. 순서변경 지원 |
| FR-222 | **마일스톤 행 [⋯] 액션 메뉴**(프로젝트 목록과 동일 패턴): ✎ 수정 / ✕ 삭제. 삭제 시 확인 대화상자 — 관련 프로젝트는 삭제하지 않고 마일스톤 연결만 해제(`ms` 필드 초기화) |
| FR-221 | 마일스톤은 다수의 프로젝트를 가진다(1:N). **마일스톤명 클릭 → 프로젝트 화면**(`projects.html?dept=…&ms=…`)으로 전환해 관련 프로젝트 목록을 필터 표시. 필터 배너에 건수·해제·Product&Goal 복귀 링크 제공 |
| FR-230 | 새 Product 추가 (관리자 권한) |

## 4. 스프린트 보드 (`sprint.html`)

| ID | 요구사항 |
|---|---|
| FR-400 | **프로젝트 스코프 보드**: 스프린트는 프로젝트 소속(1:N). 프로젝트 진입 시 그 프로젝트의 스프린트 칩(예정/진행중/완료 · 기간 표시)을 **다중 선택**해 조회 — `전체` / 개별 조합. 기본 선택 = 진행중 스프린트. 선택 상태는 URL(`?sprints=`)에 반영해 딥링크 가능 |
| FR-400a | 프로젝트 미지정 진입(사이드바) 시 전체 프로젝트의 **진행중 스프린트 통합 뷰** + 프로젝트 셀렉터 제공. 완료율 미터는 선택 범위 기준 |
| FR-400b | 다중 스프린트 표시 중에는 카드에 소속 스프린트 태그(`S26-17`)를 표시. 이월 태스크에는 `↻ 이월 n회` 배지(누적 횟수), 완료 스프린트 조회 시 이월 처리된 태스크는 `↻ 다음 스프린트로 이월됨`으로 완료 영역에 표시 |
| FR-401 | 칸반 컬럼 = 6단계 고정: Intake 협의 / 데이터 준비 / EDA / 모델링 / 파이프라인 / 서비스 개발 |
| FR-402 | 카드: 태스크 ID·프로젝트, 제목, 담당자, 목표일(D-day, 지연 강조), 첨부 수, **현재 단계 체류일**. 평균×1.5 초과 시 ⚠ 강조 |
| FR-410 | 카드 드래그&드롭으로 단계 이동. 기본은 오른쪽(다음 단계)만 허용, 되돌림은 사유 입력 모달 후 허용. 이동 시 StageLog 자동 기록 |
| FR-411 | 단계 완료 이동 시 해당 단계 산출물 요약(note) 입력 프롬프트 |
| FR-420 | 새 태스크 모달: 제목·프로젝트·담당자·시작일·목표 종료일·**Deliverable(필수)**, 스프린트(백로그 허용), Git 브랜치 자동 제안(읽기 전용 미리보기) |
| FR-430 | 프로젝트/담당자 필터. 완료 태스크는 보드 하단 접힘 영역에서 열람 |
| FR-440 | **스프린트 관리 모달**: 스프린트 목록(기간·상태·태스크 수) + 새 스프린트 생성. 이름은 ISO 주차 기준 자동 채번(`Sprint YYYY-WW`), 시작일 입력 시 2주(10영업일) 종료일 자동 제안, 수정 가능 |
| FR-441 | 스프린트 편집: 예정/진행중 스프린트의 기간·상태 수정 (변경 사유 입력, 이력 기록). 완료된 스프린트는 편집 불가(잠김) |
| FR-442 | **스프린트 종료**: 미완료 태스크 처리 방법 선택(다음 스프린트 이월 / 백로그 이동 / 개별 선택) 필수. 이월 횟수를 태스크에 표시해 반복 이월 추적. 회고 메모(선택)는 스프린트 리포트에 포함 |

## 7. KPI 모니터링 (`kpi.html`)

digitaltwin.retail.vehicle의 KPI 기반 업무 관리 방식 이식 — **전사 KPI는
영역(재무/사업/지속경영) 소속이며 부서(Product)와 독립**이다. 어느 부서의
프로젝트든 KPI에 연결할 수 있어, 부서간 협업 KPI는 여러 Product의
마일스톤·프로젝트가 결합되어 결과가 나오는 것을 지표 중심으로 추적한다.

| ID | 요구사항 |
|---|---|
| FR-700 | 상단 스탯 타일 5종: 종합 달성률(측정 KPI 가중 평균), 측정 커버리지, **데이터 연동률**(연동 지표/전체, 진행중 병기), 위험 지표 수(<92%), 프로젝트 미연결 지표 수 — 지표 단위 = leaf(하위 지표 또는 하위 없는 KPI) |
