# 01. 비전과 목표 — AI/Data North Pole

## 1. 왜 만드는가 (빅픽처)

회사를 **데이터 기반 의사결정(Data-driven Decision Making)** 조직으로 전환한다.
이 도구는 형태상 태스크 관리 툴이지만, 실제 역할은 전사가 같은 방향을 보게 하는
**North Pole(북극성)** 이다.

- 모든 부문의 데이터 과제가 **한 곳에서 시작되고, 한 곳에서 추적되고, 한 곳에서 회고**된다.
- 진행 기록(단계 로그, Git 커밋, 요청 처리 시간)이 쌓이면 그 자체가
  "어디에 병목이 있는가", "보이지 않는 업무량이 얼마인가"를 말해 주는 데이터가 된다.
- 이 데이터가 다시 **부문별 Goal을 매년 구체화·수정하는 근거**로 돌아온다.

## 2. 조직 모델: 부문 = Product

Sales, Finance, Marketing, Product Planning, Service 5개 부문을 각각 하나의
**Product**로 정의한다. 부문은 단순한 필터 값이 아니라 Goal과 마일스톤을 가진
관리 단위다.

```
Product (부문, Goal 보유)
 └─ Milestone (분기/반기 단위 이정표)
     └─ Project (담당자·우선순위 관리)
         └─ Task (스프린트 배정, 6단계 파이프라인)
             └─ StageLog / Git 커밋 / 수동 로그
```

## 3. Goal 운영 원칙: "미완성이어도 등록한다"

부문별 Goal은 처음부터 완성될 필요가 없다. 다음 3단계 상태로 관리한다.

| 상태 | 의미 |
|---|---|
| 초안 (draft) | 방향 문장만 존재. KPI·범위 미정 |
| 구체화중 (shaping) | 프로젝트를 진행하며 KPI와 범위를 채워가는 중 |
| 확정 (fixed) | 해당 연도 KPI까지 확정. 변경 시 이력 기록 |

- Goal의 모든 변경은 이력으로 남긴다 (누가, 언제, 무엇을, 왜).
- **매년 4분기**에 해당 연도의 프로젝트 실적·회고 데이터를 근거로 다음 연도 Goal을
  확정하는 사이클을 돈다.

## 4. 실행 모델: Task의 6단계 파이프라인

모든 태스크는 아래 단계를 순서대로 거친다. (분석 성숙도에 따라 일부 단계는
"해당 없음"으로 건너뛸 수 있으나, 건너뛴 사실도 기록한다.)

1. **Intake 협의** — 요청자와 범위·기대 산출물 합의
2. **데이터 준비** — 수집·적재·정합성 검증
3. **EDA** — 탐색적 데이터 분석 (요청서의 "EAD"는 EDA로 표기 통일)
4. **모델링** — 모델 개발·실험
5. **파이프라인** — 재학습·배치·배포 자동화
6. **서비스 개발** — 결과를 사용자 화면/API로 노출

각 태스크는 **시작일·목표 종료일·Deliverable(완료 판단 기준 산출물)** 을 필수로
가진다. 단계 진입/완료 시각은 StageLog로 자동 기록되어 단계별 소요시간 분석의
원천이 된다.

## 5. 유입 관리: 모든 요청은 기록에서 시작한다

이메일·전화·회의·요청서 등 어떤 채널로 들어와도 먼저 **Request(요청)** 로 등록한다.

- 요청 원문(이메일 .eml, 요청서 파일)을 첨부로 보존한다.
- 처리 방침은 4가지: **단순 리턴 / 태스크 전환 / 프로젝트 전환 / Product 신설 논의**.
- **단순 리턴도 반드시 기록**한다 — 회신 일시, 회신 첨부, 접수~리턴 소요 시간.
  단순 응대에 쓰는 시간을 데이터로 만들어야 "반복 요청의 자동화"라는 다음
  프로젝트 후보가 보인다.

## 6. 로깅 원칙: Git이 1차 기록이다

- 태스크 생성 시 브랜치 규약(`feature/DT-<번호>-<slug>`)을 제안한다.
- 커밋 메시지에 `[DT-<번호>]`를 포함하면 해당 태스크의 활동 로그에 자동 연결된다.
- 코드가 없는 작업(협의, 문서)은 화면에서 수동 로그를 남긴다.
- Git 커밋 + 수동 로그 + 단계 전환 + 리턴 기록이 **하나의 타임라인**으로 합쳐져
  다른 부문 누구나 진행 상황을 투명하게 볼 수 있다.

## 7. 성공 지표 (도구 자체의 KPI)

| 지표 | 목표 |
|---|---|
| 요청 기록률 | 유입 요청의 100%가 Request로 등록 |
| 단계 로그 자동화율 | 활동 로그 중 Git 자동 수집 비율 ≥ 60% |
| 평균 단계 리드타임 | 분기마다 병목 1개 단계 개선 (측정 가능해지는 것 자체가 1차 목표) |
| Goal 구체화 | 연말까지 5개 부문 모두 "구체화중" 이상 |

## 8. 단계적 도입

1. **Phase 0 (현재)** — HTML 프로토타입으로 화면·데이터 구조 검토 (`prototype/`)
2. **Phase 1** — 기존 서비스 세부 메뉴로 편입, Request/Project/Task 수기 운영
3. **Phase 2** — Git webhook 연동, 단계별 소요시간 대시보드 자동화
4. **Phase 3** — 연간 Goal 회고 리포트 자동 생성, 이메일 수신함 연동(자동 Request 초안)
